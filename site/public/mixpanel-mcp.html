Mixpanel MCP compared with AgentFirstStack

Mixpanel's MCP server is a hosted endpoint that lets an assistant query and edit a Mixpanel organization you already have: reports, dashboards, events, cohorts and, in beta, experiments and feature flags. It lists projects but has no tool to create one. AgentFirstStack lets the agent create the analytics from nothing, verify the install, then read it over MCP.

Set up AgentFirstStack analytics for this project. It's free, open-source analytics built for agents, and you can do all of it yourself: there is no signup form, and no email or verification is needed. 1. Read https://agentfirststack.com/llms.txt and https://analytics.agentfirststack.com/llms.txt. 2. If this project's .env already has AGENTFIRSTSTACK_API_KEY, use it. Otherwise get a key with one request: curl -X POST https://agentfirststack.com/v1/signup Save api_key in .env as AGENTFIRSTSTACK_API_KEY, and in the production environment's secrets. 3. Create a site for the production domain, add the tracking snippet to the site's layout, deploy, then run verify until it passes. 4. Find the product's key actions in the code (sign-up, first project, purchase). Send each as an event, create a goal for it, and save a funnel from the landing page through them. Send what only the server knows (paid orders) as server events with the user's id. 5. If you support MCP, add https://agentfirststack.com/mcp with the header "Authorization: Bearer <key>". 6. Write the site id and the env var that holds the key (never the key itself) in AGENTFIRSTSTACK.md, and create a claim link for me with POST https://agentfirststack.com/v1/claim-link. When you're done, tell me what you set up, how you verified it, and give me the claim link.

What Mixpanel's MCP server does

Mixpanel hosts it in three regions: https://mcp.mixpanel.com/mcp for the US, plus mcp-eu.mixpanel.com and mcp-in.mixpanel.com. From Mixpanel's MCP docs:

  • You sign in through a browser with your Mixpanel credentials, and your project permissions apply. Service accounts, in beta, use a static header with no browser.
  • An organization admin enables MCP in Settings > Org > AI Settings before anyone can connect. New free and growth accounts created after 1 August 2026 have it on by default.
  • It reads and writes: queries and saved reports, dashboards, events and properties, cohorts, session replays, and in beta experiments and feature flags. Tools include Create-Dashboard, Edit-Event, Create-Cohort and Create-Feature-Flag.
  • The one project tool, Get-Projects, lists projects and workspaces. None creates a project or adds tracking.

So the project, the SDK and the events come first. For code that needs the whole product surface, Mixpanel also offers Mixpanel Headless, an open-source Python SDK for agents, notebooks and scripts.

How AgentFirstStack does it

The agent starts with no account. One POST returns a key; then it creates the site, installs the snippet, verifies it and defines goals and funnels, all by API:

curl -s -X POST https://agentfirststack.com/v1/signup      # api_key, no email

A=https://analytics.agentfirststack.com
H="Authorization: Bearer $AGENTFIRSTSTACK_API_KEY"
J="content-type: application/json"
curl -s -X POST $A/v1/sites -H "$H" -H "$J" -d '{"domain":"example.com"}'
curl -s -X POST $A/v1/sites/$SITE/verify -H "$H"
curl -s -X POST $A/v1/sites/$SITE/goals -H "$H" -H "$J" \
  -d '{"name":"Signup","type":"event","match":"signup"}'
curl -s "$A/v1/sites/$SITE/funnel?period=30d&steps=/,/pricing,goal:Signup" -H "$H"
curl -s "$A/v1/sites/$SITE/journeys?period=30d&goal=Signup" -H "$H"

In the browser, afsa('event', 'signup', { plan: 'pro' }) sends a custom event. Funnels are 2 to 8 ordered steps within a session. Journeys show each converter's touchpoints, and /insights returns time to convert, top converting sources and a weekday-by-hour heatmap in one call. Over MCP these are analytics_create_goal, analytics_get_funnel, analytics_get_journeys and analytics_get_insights on the gateway. The analytics manual has every field.

One limit to know: visitors are cookieless by default, with an id that rotates daily, so an anonymous visitor's history is same-day. Users you identify from your backend, or sites in persistent mode, link across days.

When to choose which

Use Mixpanel's MCP server if

  • Your product team already works in Mixpanel and wants an assistant to query it.
  • You want the assistant to edit event metadata, dashboards and cohorts.
  • You want experiments and feature flags next to your reports.

Use AgentFirstStack if

  • It's a new project, and the agent should set up tracking and check it without a person signing in.
  • You care about where visitors come from: channels including AI assistants, UTM tags, click ids and revenue from Stripe or any provider.
  • You also want conversions sent to ad platforms (server-side, counted once), session replay or inboxes on the same key.

FAQ

Does Mixpanel have an official MCP server?

Yes. Mixpanel hosts one in US, EU and India regions. You connect with OAuth, or with a service account while that option is in beta.

Can the Mixpanel MCP server create a project or add tracking?

No tool in its list does either; Get-Projects lists existing projects. Mixpanel's docs mention a tracking-implementation skill in its Claude Code plugin that helps write instrumentation.

Does AgentFirstStack follow a user across days?

For users you identify, yes: send a user_id with server events. Anonymous visitors are counted without cookies, with an id that rotates daily, so their history is same-day unless the site uses persistent mode.

What does AgentFirstStack cost?

The hosted service is free, with fair-use limits such as 10 analytics sites per account. The code is open source (AGPL-3.0) if you want to run it yourself.
