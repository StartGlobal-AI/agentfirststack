Server-side conversion tracking for Meta, Google Ads, TikTok and GA4

Server-side conversion tracking sends each conversion from a server to the platform's API: Meta's Conversions API, Google Ads through the Data Manager API, TikTok's Events API and GA4's Measurement Protocol. The browser pixel sends the same event with the same id, so a blocked pixel no longer loses the conversion and each platform counts it once.

Updated 4 November 2026

How it works

  1. One snippet loads the container. When a conversion fires (a thank-you page, a form submit, a dataLayer event), the browser tags send it to each pixel with one event_id, and the same event goes to AgentFirstStack.
  2. Ad click ids from the landing URL (gclid, fbclid, ttclid and others) are stored with the visitor, so a purchase days later still credits the click. Emails and phones are hashed before anything is sent.
  3. The service calls each platform's conversion API with the owner's credentials and the same event_id. Failed calls are retried.
  4. Your backend reports what the browser can't see (paid orders, qualified leads) with POST /v1/containers/:id/events, joined to the visitor by visitor_id.
  5. GET /v1/containers/:id/events shows what each platform answered.

What each platform needs

The IDs and tokens belong to the ad account owner. They're sealed at rest and never returned in responses.

Start with the browser tags, which need IDs only, and add server-side destinations as the owner provides tokens. setup lists what's missing and where the owner finds each value; GET https://tags.agentfirststack.com/v1/schema lists every field with its format.

Set it up by API

T=https://tags.agentfirststack.com
H="Authorization: Bearer $AGENTFIRSTSTACK_API_KEY"
J="content-type: application/json"
curl -s -X POST $T/v1/containers -H "$H" -H "$J" -d '{"domain":"example.com"}'
# install the returned <script> in <head>, deploy, then:
curl -s -X POST $T/v1/containers/$C/scan -H "$H"
curl -s -X POST $T/v1/containers/$C/setup -H "$H" -H "$J" -d '{
  "platforms": {
    "meta": { "pixel_id": "1234567890123456", "access_token": "EAAB..." },
    "ga4": { "measurement_id": "G-ABC123XYZ", "api_secret": "..." }
  },
  "conversions": [{
    "name": "purchase", "when": { "data_layer_event": "purchase" },
    "value": { "data_layer": "ecommerce.value" }, "currency": "USD",
    "transaction_id": { "data_layer": "ecommerce.transaction_id" }
  }]
}'
# -> draft, validation, destinations, missing[]: what's still needed and where
curl -s -X POST $T/v1/containers/$C/destinations/$D/test -H "$H"   # test mode
curl -s -X POST $T/v1/containers/$C/publish -H "$H" -H "$J" -d '{"note":"purchase"}'
curl -s "$T/v1/containers/$C/events?since=1h" -H "$H"

The test call returns the platform's own answer. Over MCP the same calls are tags_setup_conversion_tracking, tags_test_destination, tags_publish and tags_get_event_log on the gateway. The tags manual has the full config format, consent settings and limits.

How each platform counts it once

  • Meta matches the pixel's eventID to the Conversions API's event_id, and the pixel's event to event_name, within 48 hours. Meta recommends running the Conversions API alongside the pixel (Meta's dedup guide).
  • TikTok deduplicates pixel and Events API events with the same event and event_id, within 48 hours, and records the first one it receives (TikTok's help article).
  • Google Ads counts a second conversion with the same transaction ID for the same action as a duplicate (Google Ads help). The service sends your order id as the transaction ID, or the event_id when there is none.
  • GA4 doesn't deduplicate by event id, so the service skips a browser conversion's server copy when the browser tag already sent it. The server copy covers browsers that blocked the GA4 tag, as long as the site serves AgentFirstStack from its own domain.

Backend events need one step from you. Read afst('get','event_id') on the page, pass it with the checkout or signup request, and send it as event_id:

curl -s -X POST $T/v1/containers/$C/events -H "$H" -H "$J" -d '{"events":[{
  "name": "purchase", "event_id": "'$EVENT_ID'", "visitor_id": "'$VISITOR_ID'",
  "order_id": "T123", "value": 49, "currency": "USD", "email": "jane@example.com"
}]}'

Without it, platforms that also got the pixel event count the conversion twice.

Google Ads and the Data Manager API

Google's Google Ads API docs say that since 15 June 2026, UploadClickConversions requests fail for projects with no upload activity for that feature between 17 December 2025 and 15 June 2026, and point new offline click conversion integrations to the Data Manager API. That API doesn't need a developer token (upgrade guide). The google_ads destination uses the Data Manager API by default, and its test call runs with validateOnly, so nothing is recorded.

FAQ

Do I still need the browser pixel?

Meta recommends running the Conversions API alongside the pixel, with deduplication. The pixel sees on-page activity; the server copy adds what only your backend knows, and conversions your backend reports reach Meta even when an ad blocker stopped the pixel. Browser conversions reach AgentFirstStack only when the site serves its scripts from its own domain (the first-party proxy), since ad blockers block third-party collectors. AgentFirstStack sends both with one event id.

Do I need server-side GTM to use the Meta Conversions API?

No. The Conversions API is an HTTP API your own server can call. Server-side GTM is one way to call it, your backend is another, and AgentFirstStack Tags is a third.

Does it handle consent?

Yes. setup defaults to eea_opt_in: visitors in the EEA, the UK and Switzerland start with consent denied until your banner grants it. Google Consent Mode v2 states are passed to gtag, and blocked tags fire once consent is granted.

How do I know a platform received a conversion?

Run the destination test, which sends a test event in the platform's test mode and returns its answer. After real traffic, the event log shows each conversion's status and response per platform.
