Umami alternative: open-source analytics an AI agent sets up

Umami is MIT-licensed, cookieless web analytics you can self-host with Node.js and PostgreSQL, or use as Umami Cloud, from a free Hobby plan (100K events a month, one website, no API access) to Pro at $20 a month (as of 6 November 2026). AgentFirstStack Analytics is open source and cookieless too, under AGPL-3.0 with an MIT tracker, but built so an AI agent can create the account, the site and the goals over REST and MCP, and check its own install. Umami is the better choice if you want a permissive license, a mature dashboard your team will use daily, or to self-host on any server with Postgres.

What Umami is

Umami is web analytics under the MIT License. Self-hosting needs "A server with Node.js version 20.19 or newer (22 LTS recommended)", and "Umami supports PostgreSQL (minimum v12.14) databases" (Install, as of 6 Nov 2026). Its FAQ says: "Umami's web tracker does not use cookies" (FAQ).

On Umami Cloud, web analytics, custom events, funnels, goals, journeys, retention, UTM, revenue, attribution, segments and cohorts are on every plan, and session replays and heatmaps on Business and Enterprise (Umami Cloud, as of 6 Nov 2026). The plans (umami.is/pricing, as of 6 Nov 2026):

For agents: Umami's REST API can create a website (POST /api/websites with a name and domain: API reference) and read stats. On Cloud, API keys are created in Settings > API keys and each is "limited to 50 calls every 15 seconds" (API key). Umami's official MCP server reads data only: "No tool can change settings, create websites, or delete data", and on Cloud it needs the Pro plan or above (MCP, as of 6 Nov 2026). Signing up for Cloud takes a 6-digit email code and a choice of US or EU region (Sign up).

How AgentFirstStack Analytics differs

The analytics are comparable in spirit: cookieless, privacy-friendly, open source. The difference is who operates the tool.

  • No signup form. POST https://agentfirststack.com/v1/signup returns a key. The agent creates the site, gets the install code for the framework, adds goals and checks the install; a person claims the project at the end with a link and their Google sign-in.
  • Writes over MCP, not only reads. The same key works on a REST API and an MCP server that can create sites, goals, funnels, alerts, reports and segments, record payments and run read-only SQL. Read-only keys see only the read tools.
  • Checks the agent runs. verify fetches the live page and checks the snippet, the script and the Content-Security-Policy; ?afsa_debug=1 marks the agent's own visit as test traffic it can watch in realtime; the setup check returns "ready": true or a list of fixes.
  • Beyond pageviews: server events from your backend, revenue from Stripe (or Polar, Paddle and LemonSqueezy by webhook), AI crawler visits reported by your server, imports from GA4, Plausible and other tools, scheduled email reports and alerts, Core Web Vitals and scroll depth.
  • Replay and tags on the same key. Session replay with heatmaps, and a tag manager with server-side conversion APIs, are separate services in the same project, free on the hosted version.

Like any hosted script, ours can be blocked: the default snippet loads from analytics.agentfirststack.com. Serve it from your own domain: a first-party domain (one CNAME, such as edge.example.com, from POST https://agentfirststack.com/v1/first-party-domains) or a path on your own domain (/_a/*) with the proxy configs from GET /v1/sites/:id/install.

When to choose which

Use Umami if

  • You want the MIT License, with no obligation to share changes to a hosted fork.
  • You want to self-host on your own server or VPS with Postgres, not on Cloudflare.
  • People on your team will use the dashboard every day, and you want a mature one with a large community behind it (Umami on GitHub).
  • One small site fits in the free Hobby plan and nobody needs API access.

Use AgentFirstStack if

  • An agent should set up analytics from nothing, keep it current and answer questions, without a person creating accounts or keys.
  • You want API and MCP access, writes included, on the free plan.
  • You also want session replay, a tag manager with server-side conversion APIs, or an email inbox for the agent, on the same key.

Moving from Umami

Run both for a week. The agent keeps Umami's custom event names as goal names, imports Umami's daily totals with POST /v1/sites/:id/imports {"source":"other","tool":"umami","rows":[{"date","visitors","visits","pageviews"}]}, and GET /v1/sites/:id/imports/compare checks our daily visitors against Umami's for the days both ran. Remove Umami's script when the numbers agree and you say so.

FAQ

Is AgentFirstStack open source like Umami?

Yes, under a different license. Umami is MIT. AgentFirstStack is AGPL-3.0, and its browser scripts, the tracker included, are MIT. AGPL means that if you run a modified version as a service for others, you share your changes.

Can an AI agent set up Umami?

Partly. Umami has a REST API that can create websites, and an official MCP server that reads data. On Umami Cloud a person signs up and enters a 6-digit email code first, and API and MCP access start on the Pro plan. On a self-hosted instance, an agent can script it once someone has deployed it.

Is Umami's MCP server read-only?

Yes. Umami's docs say no tool can change settings, create websites or delete data. AgentFirstStack's MCP tools can also create sites, goals, funnels, alerts and reports, with write tools hidden from read-only keys.

Can I move my Umami history to AgentFirstStack?

The daily totals, yes: POST /v1/sites/:id/imports with source other, tool umami and rows of date, visitors, visits and pageviews from Umami's export or API. Keep your custom event names so goals line up. Keep Umami running for a week and compare with GET /v1/sites/:id/imports/compare.

Do both work without cookies?

Yes. Umami's FAQ says its tracker doesn't use cookies. AgentFirstStack's tracker sets none by default either: a visitor is a hash of a daily salt, the site, the IP address and the user agent.
