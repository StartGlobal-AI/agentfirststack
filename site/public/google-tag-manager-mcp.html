Google Tag Manager MCP compared with AgentFirstStack Tags

Stape's open-source Google Tag Manager MCP server lets an agent edit a GTM account you already have: sign in with Google, then create containers, tags, triggers and variables, and publish versions. AgentFirstStack Tags is a tag manager an agent creates from nothing, with server-side delivery to Meta, Google Ads, TikTok and GA4 built in.

The Google Tag Manager MCP server

The GTM MCP server compared here is stape-io/google-tag-manager-mcp-server, developed and maintained by the Stape team under Apache-2.0. It calls Google's Tag Manager API with your Google credentials:

  • The hosted server is https://gtm-mcp.stape.io/mcp. In Claude Code: claude mcp add --transport http gtm-mcp-server https://gtm-mcp.stape.io/mcp, then sign in with Google when it first connects.
  • A local CLI takes a service account key or a refresh token instead, so no data passes through Stape's server.
  • It has 20 tools, most of them one per GTM resource with an action parameter: gtm_container, gtm_tag, gtm_trigger, gtm_variable, gtm_version and so on. Tags, triggers, variables and containers can be created; versions can be published.
  • The account tool only gets, lists and updates. That matches the API: Google's accounts resource has no create method, so a person creates the GTM account first.

Server-side GTM is a second piece. Google's server-side tagging docs say it runs on a server you control, in your own Google Cloud project or another environment. Stape provides hosting for it, and its separate Stape MCP server (https://mcp.stape.io/mcp, with a Stape API key) manages Stape containers, logs and billing.

How AgentFirstStack Tags works

One snippet on the site, and everything else by API or MCP. The browser side fires pixels; the server side calls each platform's conversion API with the owner's credentials. There is no tagging server to run.

T=https://tags.agentfirststack.com
H="Authorization: Bearer $AGENTFIRSTSTACK_API_KEY"
J="content-type: application/json"
curl -s -X POST $T/v1/containers -H "$H" -H "$J" -d '{"domain":"example.com"}'
# install the returned <script> in <head>, deploy, then:
curl -s -X POST $T/v1/containers/$C/scan -H "$H"      # tags, forms, thank-you pages
curl -s -X POST $T/v1/containers/$C/setup -H "$H" -H "$J" -d @setup.json
curl -s -X POST $T/v1/containers/$C/draft/validate -H "$H"
curl -s -X POST $T/v1/containers/$C/destinations/$D/test -H "$H"   # its answer
curl -s -X POST $T/v1/containers/$C/publish -H "$H" -H "$J" -d '{"note":"purchase"}'

scan reports what the pages already load (GTM containers, G- and AW- tags, Meta and TikTok pixels, other analytics and replay tools such as Plausible or Hotjar), the forms and the likely thank-you pages, and suggests a config. draft/import brings a GTM container over, from its export or the Tag Manager API.

setup takes conversions in plain terms ("purchase when the dataLayer gets a purchase event") and writes a validated draft with the tags, triggers and variables, plus a list of the IDs and tokens still missing and where the owner finds each.

Published versions are kept (the last 10 on the hosted service), and rollback moves the live pointer back. destinations/:id/test sends a test event in the platform's test mode and returns its answer, and the event log shows what each platform received. Over MCP the same calls are tags_scan_site, tags_setup_conversion_tracking, tags_test_destination and tags_publish. The tags manual has the full config format.

When to choose which

Use Google Tag Manager and its MCP server if

  • Your marketing team already works in GTM and you want an agent to help edit it.
  • You depend on tags or community templates that AgentFirstStack doesn't have.
  • You already run server-side GTM, on Google Cloud or Stape.

Use AgentFirstStack Tags if

  • It's a new site, and the agent should set up conversion tracking end to end.
  • You want the Meta Conversions API, Google Ads and TikTok server-side without running a tagging server.
  • You want the browser and server copies of a conversion to share one event id, so each platform counts it once (how dedup works).

FAQ

Who maintains the Google Tag Manager MCP server?

The Stape team, under Apache-2.0. It calls Google's Tag Manager API with your own Google credentials, either through Stape's hosted endpoint with Google sign-in or as a local CLI with a service account.

Can a GTM MCP server create a GTM account?

No. The Tag Manager API's accounts resource has get, list and update, but no create. A person creates the account in GTM; the MCP server can then create containers in it.

What's the difference between the Stape MCP and the GTM MCP?

The GTM MCP server edits Google Tag Manager itself. The Stape MCP server manages your Stape account (containers hosted on Stape, logs, billing) with a Stape API key.

Can AgentFirstStack import my GTM container?

Yes. POST /v1/containers/:id/draft/import with format: "gtm" takes the export file (Admin > Export Container) or the lists from the Tag Manager API or its MCP server, with a dry run first. GA4, Google Ads, Custom HTML and Image tags, the common ad platform templates and nearly every trigger and variable map; the report names anything that doesn't, such as Universal Analytics or Floodlight. When you publish, remove GTM's snippet in the same change, or its tags fire twice.
