# Feature parity: Google Analytics 4 vs AgentFirstStack Analytics (2026-11-04)

GA4 facts come from developers.google.com and support.google.com (links per row, all fetched or
status-checked on 2026-11-04). Our facts come from `analytics/src/llms.ts`, `analytics/src/mcp.ts`,
`analytics/src/service/*`, `analytics/src/do/engine.ts`, `analytics/src/lib/*` and
`analytics/src/tracker/index.ts`. Companion: `docs/research/analytics-landscape.md` (multi-vendor,
2026-11-03; some of its "AFS today" cells are stale: scroll depth, 404s, forms, Web Vitals,
annotations and comparisons have shipped since).

**Legend.** Status: **Have** (the GA4 capability exists, possibly in another shape), **Partial**,
**Missing**. Decision: keep, build, adapt (build it differently, said how), skip (why), or
"via X-n" (closed by the build in row X-n). Effort: S (days), M (1-2 weeks), L (more). Proposed API
follows our conventions: `/v1/sites/:id/...`, hyphenated path segments, snake_case JSON, MCP read
tools vs write tools (`tools.write`), idempotent creates by natural key, `next_steps`, hints.

- **Already ahead of GA4:** retroactive goals, unsampled per-site SQL, per-site retention up to 10
  years, 31-day server backdating (GA4 MP: 72 h), Web Vitals p75 per page, max scroll depth,
  renewal vs new revenue from a payment ledger (Stripe or any provider), exclusions with dry run,
  install verification with fixes, one-request signup, time comparisons on every row and bucket.
- **Biggest gaps for real users:** nothing pushes (no alerts, no scheduled reports); no GA4
  engagement vocabulary (engaged sessions, engagement rate); no first-touch (user acquisition),
  retention cohorts, attribution models or path exploration; no Search Console or ad-cost data;
  no saved segments; no ecommerce items; no metadata endpoint telling an agent which event names
  and prop keys a site has.
- **Data-quality risk found in the audit:** a Direct session adopts the first real source it sees
  (`do/engine.ts` ~l.564-580), and only same-site referrers are ignored (`lib/channel.ts`
  `sameSite`). A Direct visitor who returns from a hosted checkout (checkout.stripe.com,
  paypal.com) with a referrer re-attributes that session, and the purchase linked to it, to
  Referral; a return after 30 minutes opens a new Referral session. Not verified against each
  processor's live Referrer-Policy. Fix: CO-19.
- **Cookieless limits that shape the API:** `visitors` is `COUNT(DISTINCT visitor_id)` and
  anonymous ids rotate daily, so a multi-day `visitors` is a sum of daily uniques, not GA4
  `totalUsers`. Retention, first-touch, attribution, user properties and audiences only see
  multi-day history for identified users (`user_id`) or `visitor_id_mode: persistent`. Every new
  endpoint in these areas returns `identity: {mode, note}` like `get_visitor` does today.

## Prioritised build list

Order = what real users (agent-built SaaS, content and small-shop sites, mostly with Stripe) hit
first: correct numbers, then what an agent needs to query well, then GA4 vocabulary, then push,
then bigger analyses.

1. **CO-19 unwanted referrals with payment-processor defaults** (S). Revenue attribution can be
   wrong today for hosted checkouts; cheapest high-impact fix.
2. **DA-18 get_schema** (S). An agent can't filter on event names and prop keys it has never seen.
3. **DM-2, DM-11, DM-12, DM-13 GA4-vocabulary metrics** (S): engaged_visits, engagement_rate,
   engagement_time, visits_per_visitor, events_per_visit, visit_conversion_rate,
   average_order_value, revenue_per_customer. Migrating owners ask for these by name.
4. **AD-27 delete_visitor + AD-25 email redaction** (S + S). Erasure requests and accidental PII
   are compliance basics for a privacy-first product.
5. **CO-22 validate_only + DA-14/CO-17 realtime params and debug flag** (S). Setup the agent can
   verify itself (rule 6) without polluting reports.
6. **RE-22 alerts + RE-17 scheduled reports**, one delivery layer (M). Nothing pushes today, and
   an agent is not always running; signed webhooks first, email only to project members.
7. **Collection bundle** (S each): CO-4 site search, CO-7 form_start, DM-4 page_title, DM-3
   language and os_version, DM-6 utm extras, CO-23 content groups.
8. **DM-7 first-touch dimensions + DA-10 retention cohorts** (M + M). User acquisition, retention
   and LTV by channel (RE-3, RE-6, RE-14, RE-16) for sites that identify users.
9. **AD-15 Search Console import** (M). Organic search is the main acquisition channel for small
   sites; queries joined to landing pages and conversions.
10. **DM-8 ad spend import** (M). Cost, CPC, ROAS and CAC for anyone running paid traffic.
11. **AD-9 saved segments + DA-11 segment comparisons + DA-16 segment members** (M).
12. **DA-15 funnel v2 + RE-12 path exploration** (M + M).
13. **RE-19 attribution models + RE-20 conversion paths** (M + S).
14. **Query power** (M overall): DA-1 multi-dimension breakdown, DM-9 numeric custom metrics,
    DA-3 wildcard and numeric filters, DA-5/DA-6 sort and offset, RE-24 CSV.
15. **CO-12 user properties** (M).
16. **CO-10 ecommerce items** (L). High value for shops only; the largest single build.
17. **AD-16 export jobs, DA-9 currency conversion** (M each).
18. **Later, on demand**: AD-11 custom channel groups, AD-4 ingest-only keys, CO-14 consent call,
    CO-18 session timeout, CO-16 linker, AD-7 goal PATCH/counting, AD-20 change log, AD-21
    roll-ups, AD-26 auto-event settings, RE-13 segment overlap, DA-4 having, DM-1 weekday/hour,
    DM-10 identified_users, DM-19 visitor_type, CO-9 recommended names.
